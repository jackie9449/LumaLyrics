# LumaLyrics repository workflow

## Product requirements

- Main application pages, settings, the embedded floating appearance editor, import/cache/diagnostic/review dialogs share one visual language within each application theme. Liquid, Frosted and Material have distinct surface, shape and interaction tokens. Keep actual floating lyric surfaces, toolbar and lyric previews independently scoped.
- Application controls provide smooth hover, press, keyboard focus and selection feedback; page changes have short interruptible entrances. Respect both reduced-motion settings and system animation preferences, release completed clocks and unload subscriptions, retain input/command semantics and keep animation inside layout/scroll bounds.
- Application UI themes are selected in Settings. Keep theme selectors off the playback/lyrics main page.
- Liquid Glass and Frosted Glass derive readable surfaces, glows and control colors from the current cover. Preserve neutral grayscale and default fallbacks, reduced-motion behavior and interruption continuity. Material keeps its fixed palette.
- Floating desktop lyrics have independent appearance settings, previews, save/cancel behavior and scoped UI resources. Changing the application theme must not change floating lyrics, their toolbar or preview appearance. Per the owner's 2026-10-25 instruction, the appearance editor's chrome and controls follow the main application theme; floating theme selection changes only the lyric preview and actual overlay, never the Settings palette.
- Keep cache/library management and floating appearance editing inside Settings. The main left rail contains current lyrics, music browsing, Settings and diagnostics; library cache shortcuts reuse the Settings library page and must not open a second management window. Subscribe progress only while the embedded library panel is loaded and detach on page exit/close.
- Remember each floating theme's full custom appearance separately. Switching restores that theme's draft/saved state; Save persists all visited themes, Cancel discards all session drafts, and Reset affects only the current theme. Migrate the active legacy appearance without resetting it, and keep font hover outside theme profiles.
- Rounded floating glass uses a clipped compositor substrate beneath sharp WPF text. Keep that substrate non-activating, click-through, synchronized with position/DPI/visibility/opacity, and suppressed for transparent or instrumental states. Verify interior blur and retained scene color as well as clear corners; a successful native call alone is insufficient.
- Keep the glass host free of a legacy redirection bitmap, retain opaque native layered alpha for input transparency, and fade only its compositor visual. Share the lyric window's owner rather than making the substrate owned by the lyric window. Check consecutive real frames, visible fade strength and native hit testing after hide/show.
- Appearance editing stays modeless and temporarily permits dragging while preserving the user's lock/visibility preference and deliberate position changes. Font hover is a transient visual override, never a saved selection; leaving, closing, selecting, saving and cancelling must resolve the override correctly.
- Preserve existing lyric bindings, library data, playback behavior and compatibility fallbacks.
- Load tray/window icons from the embedded application asset, including when launched through the bundled Microsoft host. Own and dispose the notification icon, icon image and context menu; remove the Shell registration before releasing its resources. Verify recovery commands and actual Shell registration separately from NotifyIcon.Visible, and do not equate registration with the user's pinned notification-area visibility.
- Music Library starts with virtualized album cards and opens an album-scoped song list. Preserve shelf search/scroll on return and keep the global Songs view. Group only with confirmed native album identities or conservative source/album/artist metadata; do not infer undocumented track order or claim fully background playback without live window-state and media-session confirmation.
- Music Library song handoff must target the native `FilterTextBox`; never substitute the sidebar's global `TextBox`. Album card/detail playback must use a verified native album and its own Play button/queue, confirm the native first recording through a fresh media snapshot, and share latest-request cancellation with single-song playback. Keep live UI/recording diagnostics private and preserve the original native filter. Per the owner's subsequent instruction, confirmed song/album/Play Next selection minimizes Apple Music before returning focus. On failure/cancellation retain an originally visible window and restore an originally minimized window only for the current owner. Native readiness and media confirmation use bounded cancellable waits; a soft media-read timeout must not become an immediate failure. Observe the actual source snapshot independently of dispatcher delivery, never duplicate an attempted Play command, and prevent stale operations from activating or minimizing windows.
- The playback page has a compact actual queue on the right at 1220/980/820 widths. Keep queue rows constrained to their scroll viewport, artwork square in the wide layout, readable lyrics/transport to the left, and all three themes intact. Pause sidebar reads while hidden/minimized or while handoff is pending, coalesce artwork refreshes, and discard cancelled/stale results even if a provider ignores cancellation.
- A lower-right playback-page toggle persists queue visibility, defaults to visible for old profiles, collapses its column and expands the remaining content. Double-click/Enter in either queue view targets an exact native occurrence. Revalidate the actual current recording and ordered queue, retain duplicate occurrences, reject stale rows, and confirm both playing media and the remaining suffix. Never substitute library Play or repeated Next commands. Prefer native Invoke; WinUI's selection-only queue needs one Enter after verifying the owned foreground window, exact focused/selected row, unchanged metadata and released modifiers. Check cancellation immediately before the command, never repeat an attempted action, and minimize only after confirmation. Queue, album and song selections share latest-request cancellation; accepted insertions remain serialized.
- The playback list reads the actual native current recording and all exposed `PlayQueueListView*` sections in their native order, including `PlayQueueListViewManual` before the remaining album queue. Preserve repeated occurrences, enumerate virtualized items, label partial/unavailable snapshots, and restore native queue/history/scroll preferences. Reads must not activate or restore minimized native windows. Play Next invokes only an exact supported 插播/Play Next menu command; serialized insertions retain every accepted click, do not issue immediate Play, and confirm the actual new queue head. If that recording was already first, require an increased occurrence count. Keep library browsing state, keyboard button intent, stale-read guards and disposal cancellation intact.
- Queue dragging targets the captured native occurrence and insertion boundary. Require a complete unchanged snapshot, released modifiers and owned native input, preserve current recording/play state, release input on cancellation, and read back the actual order. Do not optimistically sort the UI. Reject indistinguishable continuous-recording swaps, preserve duplicate occurrences and native panel/scroll preferences, and keep both queue views' drop hints and edge scrolling within the viewport.
- Apple Music lyric review compares on-device OCR or accessible native text against the exact original hash and current recording. Verify the visible native crop, DPI, foreground ownership and state restoration; treat repeated/near matches as uncertain, never infer timestamps or semantic verification. Save captures, original text and review records only in personal storage, include validated records in personal backups, and exclude them from software/Git.
- Refresh Music Library artwork when background imports change, coalescing updates while visible and revalidating on reentry. Preserve browsing and playback state, retain the page on transient read failures, and discard stale thumbnails and missing-image results. Verify original PNG/JPEG content through the personal cache's `.img` paths.
- Automatically import only checked timed lyrics. Preserve manual bindings, never fabricate timestamps, and do not label missing lyrics as instrumental.
- Chinese translations have independent main/floating visibility switches in Settings, initially off, and a synchronized floating switch in the above-overlay toolbar. Keep originals, next-original semantics, offsets and blank intervals. Bind translations to exact original SHA-256 and group indexes; never retime by borrowing a different recording's timeline. Community alignment is not semantic verification. Per the owner's 2026-10-23 instruction, omit pending-review badges from visible UI while retaining AI provenance and original review records in personal storage; hiding a badge must not promote a draft to reviewed or replace manual translations. Store translations/queues/reports only in personal data; include consistent snapshots/readable JSON in personal backups and reject them from software archives.
- Floating corner strength is a 0–100% proportion of half the shorter actual edge. Migrate old pixel settings and use the same ratio for WPF masks, materials, and native compositor clips after layout/DPI changes. Fade all background optics continuously near zero opacity; keep lyric text independent.
- Confirmed instrumentals leave the main lyric area blank and suppress floating text and its empty surface. Restore the UI when vocal lyrics return.
- Map covers through Apple Music persistent IDs and confirmed album references. Count high resolution from actual image dimensions, preserve usable fallbacks, and keep personal metadata, images and downloaded lyrics out of Git.
- Keep personal data outside software directories and archives. Export readable personal lyrics/covers with consistent database snapshots; restore only into a new directory. Never replace existing personal files or silently create an empty profile when a selected location is unavailable. Validate distribution boundaries before creating a software ZIP.

- Chinese script display offers original, simplified and traditional choices shared by main and floating lyrics, saved in personal settings. Convert only display strings offline; preserve raw originals, hashes, group indexes, timing, manual bindings and translation provenance. Detectable Japanese/Korean originals stay unchanged while their Chinese translations can convert. Keep both translation visibility switches independent.
- Interface language is independent of lyric script: zh-Hans (legacy default), zh-Hant, en and ja, persisted and applied on restart. Explicitly localize application copy, formatted templates and canonical status display boundaries; never traverse arbitrary text to translate user metadata, lyrics, paths, theme IDs or stored provenance. Keep native Apple Music label recognition independent of the application language. Per the owner's 2026-11-11 request, omit main/settings page slogans and eyebrows while retaining the application titlebar.
- Keep the main Chinese script selector in the playback footer, visible only for Chinese originals or either enabled Chinese translation switch; preserve its saved choice while hidden and keep all footer actions inside narrow windows. Global shortcuts must work outside the app, retain legacy bindings, support explicit disabling and conflict reassignment, avoid repeats, suppress execution while recording a shortcut, and release registrations on exit. Only save a complete valid assignment; preserve previous registrations on failure and report any failed rollback. Native seeking compares the separately parsed title, artist and album and requires actual timeline confirmation.

## Local development records

Keep development changes in local Git and record each completed task in [docs/development-log.md](docs/development-log.md). This workflow supersedes the GitHub synchronization instructions in earlier plans and handoff packages.

1. Inspect the local branch, HEAD and working-tree changes before editing. Preserve unrelated user work.
2. Implement the requested change, run relevant unit tests and UI verification, and update release notes or instructions when behavior changes.
3. Record the date, change summary, actual validation results and any remaining checks in the development log. Commit the log with the corresponding changes using a descriptive conventional commit message. Exclude .tools, build outputs, local settings, media libraries, databases, credentials and private test data.
4. Verify the local commit and working-tree status. Report the commit SHA and any remaining verification limits.
5. Keep routine development local. Configure a GitHub remote, fetch, push, open a pull request or publish a release only when explicitly requested for that task.

## Validation

Use scripts/common.ps1 to select the bundled SDK when present. Use isolated --data-dir directories for --verify-ui checks. The packaged Microsoft host is an available fallback for the previously documented apphost startup stall. Do not infer that successful UI checks prove live Apple Music synchronization.
