# 日语原名和发行署名查词计划

**目标** 让程序自行核对 Apple Music 与网易云的发行目录，识别日文原名和主唱署名导致的错配。

**实现** 常规查询遇到日语名称或来源元数据差异时，使用 Apple 的公开搜索和查找接口取得美区和日区同版目录。凭相同曲目 ID 对照各地正式名称，再凭日文专辑、发行艺人、完整曲序、录音版本和时长核对网易云目录。匹配结果在同张专辑的查询间短期复用。C# / .NET 10，沿用现有查词和个人数据存储。

**依据** 用户要求通用处理这类标题和署名差异，录音确认和歌词自动采用继续按 [仓库约定](../../../AGENTS.md) 执行。[Apple 目录 API](https://performance-partners.apple.com/search-api)、[按 ID 查找曲目的官方说明](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/LookupExamples.html)。

## 查询发行目录

- [x] 在 `AppleReleaseCatalog.cs` 加入 `FindAsync(Track, CancellationToken)`，返回可对应的美区、日区专辑和两边的曲目元数据。先用歌名、艺人、专辑和时长定位 Apple 曲目，未查到时检索专辑。用找到的专辑 ID 分别读取两个地区的目录，校验同版曲目的 Apple ID、明确曲序和时长，并核对当前歌曲。
- [x] 在 `NetEaseLocalizedRelease.cs` 用日本地区目录的专辑名搜索网易云，名称结果太多时加艺人缩小范围。核对专辑艺人、曲目数和有据可查的发行日期。按碟号与曲序逐项核对原名、版本和时长，合作艺人明确出现在标题或艺人栏时可对应。配对必须唯一。用于发行核对的相邻曲目时长差最多 2 秒，实际采用的曲目时长差最多 1 秒。只有一首的发行版也可核对名称，主唱替代团体署名需要多首发行证据。
- [x] 接入自动与手动查词。常规匹配先执行，目录只在有关的歌词查找需要时使用。为同一专辑复用有界内存结果，限制远程请求、尊重限流及取消。网络失败保持候选和可重试状态。

## 保留证据和兼容性

- [x] 用 `NetEaseReleaseEvidence` 把已核实的 Apple 曲目、网易云专辑与曲目 ID 和实际元数据写入原有来源记录。离线回读时验证一致性。原词、偏移与译文的哈希和对齐规则都沿用现有实现。上一版的固定映射仅供此前保存的记录离线读取。
- [x] 更新查词策略版本、使用说明和界面诊断。相似标题、不同发行版、不同曲序、近似时长或同名翻唱仅在能确认是同一录音时自动采用。缺词与时间标签损坏仍可重查或手动处理。
