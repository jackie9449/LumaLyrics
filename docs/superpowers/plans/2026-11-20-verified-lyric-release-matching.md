# 按已核实的发行曲目自动查词

**目标** 让《穢れなき瑠璃色のローゼンクロイツ》的自动查词与手动搜索都能识别曲目的原名和主唱署名，逐首核对返回的歌词。

**范围** 这次登记一张经核实的发行版本，并使用可复用的曲目映射结构。Apple Music 同一专辑与曲目 ID 对应美区和日区名称。网易云专辑 38636065 与它的十首曲目逐首核对了专辑、曲序、歌名和长度，目录时长相差 0–48 毫秒。查词仍用已有的 LRCLIB 与网易云网络入口、限流和取消机制。

目录对照采用 Apple Music、发行方与网易云的公开记录。[Apple Music 美区](https://music.apple.com/us/album/1489281445)、[Apple Music 日区](https://music.apple.com/jp/album/1489281445)、[Ariabl'eyeS 发行目录](https://ariableyes.com/disc.html)、[网易云专辑](https://music.163.com/#/album?id=38636065)。

## 曲目录入与核对

- [x] 在 `NetEaseVerifiedRelease.cs` 登记该版的两个专辑名、团体名、逐首双语歌名、网易云专辑与曲目 ID、来源署名和长度。为来源返回的曲目 ID、专辑 ID、原名、署名和时长提供独立核对。Apple Music 输入必须有已登记的团体、专辑、歌名和相符时长。
- [x] 在 `Models.cs` 与 `MatchRules.cs` 增加随候选传递的 `CatalogRecordingMatch`。匹配时检查使用的是原候选，且输入仍指向同一录音。有效匹配显示「发行曲目已核对」并保留原目录元数据。沿用动态歌词、静态正文和明确纯音乐的检查。
- [x] 增加专项测试。比如 `Itoshiki Rufenburg` 对应 558560456，团体和原专辑名得到确认时通过。修改 ID、专辑、署名、版本、长度或输入目标时拒绝。

## 查词与缓存

- [x] 在 `NetEaseTranslationProvider.cs` 读指定曲目和原词。自动、手动及扩展搜索共享目录解析与映射。保留原有查询备用。把可核对的来源专辑 ID 写入原词来源记录。复查缓存及准备中文译文时应用同一录音检查和原有译文对齐。
- [x] 通过 `LyricsLookupResult` 传递目录查询结果。在 `LyricsLookupDiagnosis.cs` 区分目录曲目未确认和已确认但没有歌词。源文件的时间标签损坏时给出相应原因。补齐相关界面翻译。
- [x] 更新查词策略版本，以应用现有失效机制再次评估旧失败。用隔离库验证缓存读取、手动绑定保留和重新查询。没有可靠内容的歌曲保留可重查状态。
