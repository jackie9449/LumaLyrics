# LumaLyrics 1.3.0 Release Implementation Plan

> Execute inline under the owner's request to sync the project and publish a release on GitHub.

**Goal:** Publish the complete local development branch as `v1.3.0` with Windows x64 installer and portable downloads and verified SHA-256 files.

**Architecture:** Keep the central version and existing self-contained Windows packaging scripts. Build the release from the committed source, verify the portable payload and installer locally, then verify uploaded assets on a draft Release before publishing it as latest.

**Tech Stack:** .NET SDK 10.0.402 via `scripts/common.ps1`, locked NuGet dependencies, WPF isolated checks, Inno Setup 6.7.3, Git and GitHub Releases.

**Spec:** The owner requested syncing current development and publishing a release with an appropriate version. On November 24 the latest public release is `v1.2.0` at `879e52a`; local `main` at `31647e4` adds offline translation and manual/assisted lyric timing in addition to matching and performance fixes. Ship these compatible features in `1.3.0`.

## Global Constraints

- Follow [AGENTS.md](../../../AGENTS.md). Preserve the prior tags and the untracked developer handoff ZIP and checksum. Push only `main` and the new tag without force.
- Keep tools, test reports, local settings, databases, media, consumer model files and credentials out of Git and the distributable packages. Ship only the supported program and checked documentation.
- Use separate software-external `--data-dir` paths for package smoke tests. Installer testing must not replace an existing installation or shortcuts. Isolated UI checks do not prove synchronization against a live Apple Music client.

### Task 1: Set the version and prepare documentation

**Files:** `Directory.Build.props`, `README.md`, `docs/release-notes.md`, `docs/development-log.md`, `docs/verification-v130/README.md`, `scripts/publish-ui.ps1`.

- Confirm `git status --short --branch` and `git ls-remote --heads --tags origin`; compare the outgoing commits from `v1.2.0` and check tracked changes and history for private files. Set `Version` to `1.3.0`; leave runtime and dependencies unchanged.
- Update the two README downloads, record the new release's features and compatibility boundaries, and keep 1.2.0 history. Have the package copy the 1.3.0 verification note.
- Run `Invoke-Dotnet restore --locked-mode --source .tools/nuget-feed-b0736aa '-p:NuGetAudit=false'`, `Invoke-Dotnet build -c Release --no-restore` and `Invoke-Dotnet test -c Release --no-build --no-restore` after loading `scripts/common.ps1`. Record actual counts, constraints, and any failed checks before committing.

### Task 2: Build and validate the downloads

**Inputs:** Frozen release commit and checked Inno Setup compiler. **Outputs:** `LumaLyrics-1.3.0-portable-win-x64.zip`, `LumaLyrics-1.3.0-setup-win-x64.exe`, separate `.sha256` files and `SHA256SUMS.txt` in `artifacts/release-1.3.0/`.

- Run `scripts/publish.ps1` and `scripts/publish-installer.ps1` for the same payload. Run `scripts/test-distribution.ps1` and `scripts/verify-release.ps1 -PackageDirectory artifacts/LumaLyrics-1.3.0-portable-win-x64 -Installer artifacts/LumaLyrics-1.3.0-setup-win-x64.exe` to check the software boundary, file-by-file ZIP content, binaries, versions and sidecars.
- Launch the committed package through the bundled host and a new isolated `--data-dir`; check original-lyric acquisition, batch preparation, translation and timing. Use the install verification script only if it confirms there is no existing registration or same-name Start Menu directory. Record the actual coverage.

### Task 3: Sync and publish

**Inputs:** The validated commit and five local assets. **Outputs:** GitHub `main` and annotated `v1.3.0` pointing at the committed release, and a stable/latest Release at that tag.

- Reconfirm the remote branch/tag, create annotated `v1.3.0`, and push the branch and tag using ordinary fast-forward rules. Confirm the tag's peeled commit matches the remote branch and the package's product version.
- Create a draft at `v1.3.0`, upload both binaries and all checksums, and compare returned byte sizes and digests with local hashes. Publish the verified draft as latest. Check the public Release and its assets after publishing.
