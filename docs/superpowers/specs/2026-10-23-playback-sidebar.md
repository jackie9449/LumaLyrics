# Playback sidebar and resilient handoff

The playback/lyrics page displays a compact current playback list on its right side. It reads the same actual Apple Music queue as the library page, preserves manual insertion order and repeated occurrences, and shows current/upcoming tracks, covers, explicit loading/empty/partial/unavailable states and refresh. At 1220, 980 and 820 pixel window widths, the sidebar stays to the right without overlapping the artwork, transport controls or readable lyrics. Existing library browsing and independent floating appearance remain intact.

A slow native UI or media-property read must not immediately fail an otherwise valid recording request or activate LumaLyrics prematurely. Wait for native navigation, local filtering, exact row identity and album context to become ready within bounded cancellable deadlines. Issue the actual Play/Play Next command at most once. Media confirmation retries transient read failures and retains an in-flight slow read; it requires a fresh Apple Music snapshot for the requested recording in Playing state. New song/album requests cancel older ones, and stale completions cannot change focus or window state.

After actual song, album or Play Next confirmation, minimize Apple Music and then return focus to LumaLyrics. Defer restoration/minimization until confirmation finishes. On failure/cancellation, restore an originally minimized native window only while that operation still owns its window lifecycle. Read-only queue refreshes never restore or activate Apple Music. No personal queue, library data, lyrics, covers or diagnostics enter Git or software ZIPs.

Validate transient timeouts, delayed in-flight success, stale/wrong/non-Apple/non-playing snapshots, real deadline exhaustion, cancellation and late completion. Verify native readiness with a delayed original WPF accessibility fixture; run isolated WPF sidebar layout, themes, navigation and disposal checks. Run an explicit live Apple Music check of delayed confirmation and final minimized state, preserve the original recording/queue where verifiable, and keep full diagnostics private. Release 0.13.0, test the source and packaged app, and synchronize GitHub using a conventional commit and expected-head protection.
