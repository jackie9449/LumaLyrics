# 资料库与中文译文整合设计

日期：2026-11-03。调查基线：`0df09de007f0b8e3ca7e5d0fb2b5a39beb98fcac`。

本文配套[执行计划](../plans/2026-11-03-library-lyrics-workspace.md)，描述后续整合方案。本次只交付规划，不修改运行逻辑；已实现的本地 agent 翻译功能见[中文译文指南](../../chinese-translations.md)。

## 1. 目标与整合范围

用户希望整合资料库和中文译文功能。采用“以歌曲为中心”的管理方式：共用一份确认过的资料库清单、原词／译文／封面状态、选中集合和任务入口。

主要入口为「设置 → 资料库与歌词」，合并当前 Settings 的「资料库」与「中文译文」。主窗口的音乐浏览仍负责专辑、歌曲、歌单和实际播放，提供带上下文的管理入口，进入同一个 Settings 实例。主左栏不增加管理窗口或新的顶级页面；个人资料目录、备份和恢复仍在「个人资料」。

整合遵守下列已确认要求：

- 有可靠既有中文译文时直接使用；缺失时可交接一份批量 MD；不满意时明确选择重译。
- 原词、译文、封面和任务均显示同一首歌的真实状态；部分译文不算完整。
- 管理选中歌曲无需先播放它，播放变化不改变已选歌曲和批量目标。
- 原词时间轴、哈希、手动资料、偏移、纯音乐行为及独立译文显示开关保留。
- 六套应用主题共用现有资源和交互；悬浮歌词、工具栏和预览继续独立。

## 3. 信息结构与界面

Settings 导航保留「应用界面、悬浮歌词、常规、个人资料」，新增合并项「资料库与歌词」，移除独立的「中文译文」和旧「资料库」项。

| 内部视图 | 用户看到的内容 | 主要动作 |
| --- | --- | --- |
| 总览 | 当前资料库来源、读取状态、歌曲／原词／译文／封面概要；本轮任务摘要 | 检查资料库、定位待补齐歌曲、选择本机资料库文件 |
| 歌曲 | 一份虚拟化歌曲表，搜索、筛选、多选、所选详情 | 准备所选、直接生成本地翻译任务、明确重译所选、导入／恢复所选歌曲译文 |
| 任务 | 本次补齐、来源准备、个人 agent 批次与逐首结果、历史来源 | 打开／复制批量 MD、继续、只处理失败项、查看原因、取消指定任务 |
| 显示 | 主窗口中文开关、悬浮中文开关、小型双语示例和来源说明 | 即时保存显示偏好；不改变任何译文或任务状态 |

外层使用有界 Grid，不把完整歌曲表嵌入无限高度的 StackPanel/ScrollViewer。总览正文和详情可以滚动；歌曲与任务列表各自拥有受约束的滚动视口。

“Apple Music 资料库文件”与“个人资料目录”明确分开：前者在总览选择，后者只显示当前位置并提供进入「个人资料」的链接。不可把选中一个 Library.musicdb 当成切换个人 profile。

### 歌曲表与选择

默认列为勾选／歌曲与艺人、原词、中文译文、封面、任务。窄窗保留名称、勾选与原词／译文主状态，其余放到所选详情；歌曲名和原因可展开，不用长状态横向挤出视口。

筛选提供：全部、缺动态原词、缺中文译文、部分译文、原词更新后需重做、等待 agent、需处理。筛选可以多选：状态条件之间取并集，再与搜索条件相交。默认缺中文译文只包括已有可靠动态原词且确实需要中文的歌曲；缺原词独立呈现。

选择以 `(Source, PersistentId)` 保存，排序、搜索、筛选、刷新及离开视图不会清空仍有效的选择。显示“已选 N 首，当前可见 M 首”，可查看所选、清空、全选当前筛选结果。全选涵盖完整筛选快照，不能只选已生成的可见行。开始操作时冻结明确的 ID 集合，随后筛选变化不扩张或改变操作范围。

默认按钮只作用于已选集合，无选择时禁用；全库操作必须先明确“全选全部 N 首”。普通补齐不逐曲弹确认；重译在一个创建摘要中一次确认各首当前来源、修订和关联影响。

### 所选详情与当前播放

详情显示所选记录的原词来源、必要译文组数／已覆盖组数、译文来源、最近任务和历史。导入 LRC、参考原词校对、采用部分稿、恢复历史均按这里捕获的目标执行，而不是读取当时 ActiveTrack。打开文件选择器或异步等待后再验证同一目标与修订。

当前播放只作为独立高亮；「定位当前播放」是用户主动操作。切歌不改变管理选择。当前播放若不属于确认资料库，作为明确标注的个人曲目详情使用现有单曲功能，不自动加入资料库或计入其统计。

## 4. 状态口径

每首歌保留四个维度，不合并成单一“完成”标签：

| 维度 | 状态与规则 |
| --- | --- |
| 原词 | 缺失、待确认、手动静态原词（保留）、可靠动态原词、已确认纯音乐 |
| 中文 | 缺动态原词、无需翻译、缺失、部分 X/Y、完整 X/Y、原词已更新；手动／来源／AI 是来源属性 |
| 封面 | 缺失、可用、高分辨率、引用不可读；按确认的图片映射和实际尺寸记录，不按文件名或下载请求大小统计 |
| 任务 | 排队、正在查找、已生成待 agent、已提交待接收、已接收、部分稿待用户采用、失败／冲突／过期／已取消 |

完整译文计算：在当前原词上复用 `TranslationAlignment.NeedsChineseTranslation` 得到必要 GroupIndex 集合 R；只有当前 SourceHash 通过且 R 中每组都有非空译文，才是完整。`0 < 覆盖数 < |R|` 是部分，不能因为 Find 非 null 就算完整。中文识别沿用现有保守规则，不新增语言模型或宣称识别能力提高。

原词变化导致没有当前哈希译文、但存在同一录音的旧哈希记录时，显示“原词已更新”；旧内容保留。不同来源、时长或录音信息不能只靠类似歌名关联。任务完成不改变 Draft／Review 真实性，不新增可见“待校对”徽标。

总览以确认的活动资料库成员为分母，重复的原生成员不丢失；个人历史和旧来源记录不混入当前库。原词、译文和封面的统计是不同维度，不能相加称为已准备歌曲数。中文覆盖量同时标明“需译且已有动态原词 M 首；另有 N 首原词待确认”。错误／暂无来源属于已处理结果，不属于可用覆盖量。

本轮进度另显示：选中总数、已处理、来源已补齐、等待 agent、受阻、失败、取消。选中一首经历三个阶段，仍只算一首；导出 MD 与结果接收分别计数。

## 5. 共同准备流程

“准备所选…”默认补动态原词与中文译文，优先沿用可用资料，再查现有来源，最后为仍无可用中文的歌曲生成一份批量 MD。“同时补封面”为可选项，初始关闭，既有后台封面策略不变。

```text
冻结所选原生 ID 与当前来源
  → 核对成员和当前资料
  → 缺动态原词：按现有录音／全文／时间轴标准补原词
  → 原词可靠且需要中文：沿用已有译文，或查现有来源
  → 仍缺中文且用户本次选择生成任务：汇总到一份 batch-task.md
  → agent逐首提交，现有 Inbox 校验接收
  → 更新同一列表、覆盖统计和任务详情
```

没有可靠动态原词时记录受阻原因，不生成翻译任务、不编时间、不标纯音乐。手动静态原词不自动替换；部分已有译文保留并列为需用户选择是否重译，不借“补齐”绕过已有译文保护。

提供明确的快捷动作：只找现有来源、直接导出本地任务（离线可用）、重新制作所选、补封面。明确重译跳过现有来源查询，捕获创建摘要中的当前哈希和 Revision；新的人工修改、历史恢复或另一个任务先到后拒绝旧授权。

资料库完整成员同步与选中歌曲准备分开。只能用核验的完整清单更新 LibraryTracks/LibraryMembership 或封面主队列；选中操作过滤已有队列或使用不重置活动集合的单项方法。继续共用现有 lease、节流、联网设置、暂停和前台查词优先规则；不另起一套会同时覆盖同一歌曲的 worker。

任一来源连续失败按现有规则暂停该来源阶段，记录 TransientError，保留已保存结果。可继续安全生成有可靠原词的本地任务；不能宣称该来源确定没有译文。关闭联网后停止新的网络请求并取消在途查询，忽略不遵守取消的晚到结果。

关闭或离开 Settings 仅释放页面观察者；已接受的准备工作由 profile 级协调器继续管理，显式“暂停／取消”才停止对应操作。应用退出有序取消，保留既有队列、已生成任务和已接收成果；重启从真实保存状态重新检查未完成项，不自动重放旧的重译授权。跨视图保留选择；本版不新增跨重启自动执行的选择篮。

## 6. 任务视图与重复身份

任务视图默认当前资料库，可切换全部个人任务／历史来源。批量入口列出全部登记批次，不限最新一个。回执状态以数据库为准；已有最终文件仅表示已提交，不是已接收；agent-progress.json 只作恢复提示。

在不迁移数据库的首版中，批次成员从登记 Manifest 指向的受控分块读取，校验路径、BatchId、分块 SHA-256、JobId 和 RequestSha256。缺失／过期分块显示“成员清单不可用”，可以查看保留的个人任务，但不按相近时间或标题猜成员，也不开放不明确的整批取消／失败重试。恢复后的旧绝对路径不读、不打开，需按当前原词重新生成入口。

逐首失败可查看原因和重新检查；重试只针对该批次明确的失败集合。重新生成重译任务仍需显示当前版本摘要，不能把历史授权套到新 Revision。取消共享 JobId 时显示其影响的关联批次，不把“从当前列表移除”误作撤销底层任务。历史恢复和部分采用通过所选歌曲详情执行。

原生行身份和处理份数分开：每个 Source/PersistentId 都保留一行。当前译文存储仍按 `(Fingerprint, SourceHash)` 复用内容；重复记录不能因 Track 相同就从表中消失。完全相同的已有绑定可合并实际补缺工作，并明确所关联的原生行。

若多个原生记录共享同一旧译文存储槽，而用户只选择其中部分进行重译／导入／恢复，先阻止不明确的定向替换并列出关联影响，允许用户明确选择全部关联记录后继续；不悄悄更改未选记录。本次不重写歌词／译文主键，也不声称元数据相同就证明是同一原生录音。

只有已确认使用同一绑定、同一原词哈希和同一当前修订的关联记录可以按组处理。不同绑定／录音／时长却碰到同一旧存储键时仍拒绝写入，即使全选也不能绕过；这种历史存储歧义留待独立的数据迁移方案解决。

## 7. 音乐浏览与迁移兼容

音乐浏览中的「缓存管理」改为「歌词与译文管理」，进入同一 Settings 的总览。歌曲操作或专辑详情可带入所选原生 ID，打开歌曲页并定位／选择该范围，保留音乐浏览的专辑、搜索、排序、滚动与播放上下文。Enter／双击仍按既有播放规则执行；管理按钮的 Enter 只触发管理。

歌曲行可复用简短的原词／译文状态，专辑入口可携带已有的确认成员。状态读取不触发下载、不恢复 Apple Music、不读取实际队列、不修改专辑分组或原生播放请求。所有缓存管理快捷入口复用一个 Settings 实例。

`SelectLibraryTab()` 路由到新总览；`SelectTranslationTab()` 路由到显示视图，单曲／批量入口使用新的带目标导航 API。播放页和悬浮工具栏的译文开关继续双向同步，不增加主题选择器。

本次沿用 lyrics schema 5、translations schema 2、个人备份 manifest 2 和现有任务 JSON schema 1；不合并数据库、不重新导入个人库、不重置显示开关。新精确身份 API 与旧 Track API 并存；旧 API 无法唯一定位时明确拒绝，不使用 FirstOrDefault 随机选择成员。

## 8. 性能、验证与交付

共用后台只读状态投影，批量读原词绑定、译文内容／Revision、封面索引与轻量任务字段；不在 UI 线程逐行 Find 或解析全库原词。增量更新按变化的绑定／哈希／修订合并，丢弃旧 source/generation 结果。完整内容在详情打开时读取。

来源 generation 只在 profile／资料库来源变更时递增，不能由本轮自己的原词或译文写入触发，否则任务会取消自身；同来源的异步读取使用另一个 RequestVersion 拒绝较早读取结果。

页面只在 Loaded 且可见时订阅；Unloaded/Dispose 解绑、取消视图读取并释放动画。任务协调与 Inbox 属于应用生命周期，页面解绑不销毁它们。来源暂不可读时保留上次可确认的同来源列表和选择，标记过时并禁用不能再核验的写入；不显示成空资料库。

| 验收场景 | 必须结果 |
| --- | --- |
| 缺原词、缺译文和已有来源混在一批 | 只选一次，按阶段处理，汇总一份 MD，跳过原因清楚 |
| 手动／部分／AI／旧哈希／纯音乐 | 逐维正确计数；不覆盖手动、不虚构完成或语义已审 |
| 所选 B，当前播放 A；处理中切到 C | 导入、重译、采用、取消及恢复仍针对 B，A/C 播放不变 |
| 搜索／筛选／排序／切页／后台刷新 | 保留有效选择和滚动；冻结的操作范围不扩大 |
| 重复元数据、多来源、共享旧译文 | 原生行不丢失；歧义不随机分配；定向替换不悄悄影响未选项 |
| 框架后台原词／封面正在运行 | 共用原 lease和队列，不重复抓取，不把选中集合 Sync 成整库 |
| 取消／关闭联网／忽略取消的 provider | 不再发新请求、不接受晚到写入；其它已保存成果可用 |
| 任务文件缺失、旧 profile、个人目录不可用 | 真实显示不可用／历史，不猜新路径、不建空库 |
| 六主题与 1220/980/820；Settings 原有 640 下限 | 表格／任务／详情在各自视口内，窄窗降为纵向，键盘语义保留 |
| 3003 首、批次 100 首 | 虚拟化、后台批读与合并更新；无逐项 dispatcher 全库扫描 |

实施时增加专项并运行既有翻译、任务、资料库成员、音乐浏览、Settings 和主题检查；分发继续拒绝个人任务、原词、封面、数据库和报告。真实 Apple Music 同步与第三方 agent 语义质量分别验收，不从 UI 检查推断。
