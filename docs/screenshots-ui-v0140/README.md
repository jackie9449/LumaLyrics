# 0.14.0 播放列表开关与队列跳转验证

239 项单元测试通过（Core 49、Infrastructure 190），Release 编译零警告、零错误。源码和自包含运行包分别完成 592 项实际 WPF 布尔检查，全部通过，检查项完全一致，结果见 [源码检查](ui-check.json)和[运行包检查](ui-check.packaged.json)。较 0.13.0 增加 40 项界面检查，原有 552 项继续回归。分发边界检查通过：允许 2 个软件样例，拒绝 26 类私人文件或模型。

新增检查覆盖右下角开关的可访问名称、键盘焦点、设置保存/恢复，隐藏后停止轮询、重新打开刷新、隐藏前旧请求隔离，三种主题在 1220/980/820 宽度下的显示/隐藏布局；也检查队列单击、双击、Enter、重复位置、快速选择取消、失败与旧结果不激活窗口、关闭后的回调隔离、音乐库队列共用跳转路径，以及原生项目逐项映射、重复录音的不同原生目标和过期快照拒绝。

跳到最后一首时，已安装客户端移除列表控件并显示明确的“无待播歌曲。”。新增真实 UIA 检查验证只在原生队列面板、待播标签被选中且出现该标记时认定空队列；面板外同名文字和历史页面均不能冒充空待播列表。读取要求两次稳定观察，保留当前录音。

真实 Apple Music 1.1540.23042.0 已验证队列指定位置播放、剩余顺序、过期请求拒绝、同一首歌连续插播后跳到第二次出现的位置，以及最后一首开始后的完整空队列。重复录音测试特意使用与当前录音相同的歌曲，避免单靠媒体歌名误判；跳转后测试插播项消失，原有后续歌曲完整保留。成功后原生窗口最小化。结束时恢复原录音、完整待播顺序和暂停状态；精确播放位置受媒体会话能力限制。

当前客户端的队列行仅有选择接口，适配必须核对原生窗口前台、所选行焦点和元数据，再发送一次 Enter。未满足条件时不发送，已尝试的命令不重发。这些现场结果不代表所有客户端版本或完全后台播放。[12 项不含个人元数据的实机摘要](live-queue-jump-check.json)；原始报告保留在忽略目录，个人歌词、封面、曲目及队列不进入 GitHub 或软件包。
