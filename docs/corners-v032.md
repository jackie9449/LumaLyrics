# 0.3.2 · 悬浮窗圆角

2026-10-19。

此前歌词内容已有圆角遮罩，但原生窗口区域额外向外扩张了 2 个物理像素。系统背景模糊由 Windows 合成，透明的 WPF 像素不能阻止模糊填入这部分区域。默认窗口模板的缩放手柄也在歌词遮罩之外，导致客户区示例看似正常，实际悬浮窗仍可能在四角留下多余部分。

现在窗口使用明确的透明模板，缩放手柄位于整窗遮罩内。原生区域按 HWND 的实际物理尺寸生成，不再外扩；必须成功应用后才开启系统模糊。调整大小、切换锁定/单双行以及 DPI 变化后均重新应用区域和遮罩。外观面板中的预览仍使用相同的圆角几何。

## 验证

Windows 上运行：

```powershell
./scripts/verify-corners.ps1
```

脚本先构建，再使用新的独立数据目录运行应用，关闭联网查词和资料库预缓存。覆盖液态玻璃、雾面毛玻璃、卡片、透明四种材质，0/8/24/64 四档圆角，以及解锁双行 820 px、锁定单行 360 px 两种窗口状态，共 32 种场景。

`artifacts/overlay-corners/corners-check.json` 检查真实 HWND 区域的物理边界、中心和四角，以及整个窗口渲染后的四角透明度；另输出大圆角锁定/解锁实图。发现失败会让脚本返回错误，PR 的 Windows 检查使用此脚本并提供运行包与验证记录。

这些检查覆盖原生区域和 WPF 输出，不等于系统合成后的屏幕截图。Windows 10 的实际背景模糊观感、鼠标缩放操作以及跨显示器 DPI 切换仍需现场检查。不要将此前 0.3.1 的截图或检查记录当作本次修复的运行结果。
