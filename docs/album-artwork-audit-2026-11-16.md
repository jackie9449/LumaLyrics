# 音乐库专辑封面缺失检查（2026-11-16）

## 结论

当前专辑页的占位图来自封面关联失效，而非图片文件丢失或本轮发现的渲染故障。现行音乐库歌曲的持久 ID 与个人封面数据库的历史 ID 没有交集。音乐库按本机原生清单显示歌曲，但封面必须通过来源路径与歌曲持久 ID 精确关联；因此已有图片无法附到当前歌曲上。

## 实际验证

- 本地代码基线 main / 181b4c3；现场运行的是 ui-polish 预览包，并非刚交付的 clock-sync 包。两个版本的封面关联代码相同。
- 通过 Computer Use 查看实际音乐库页面：289 张专辑、3,086 首歌曲，当前可见卡片为占位图。未点击播放、切歌或更改个人设置。
- 使用生产 `MusicLibraryCatalog.Load()` 和 `MusicLibraryAlbums.Group()` 只读加载当前资料：3,086 首歌曲、289 张专辑，歌曲与专辑封面路径均为 0。
- 个人 `artwork.db` 有 2,949 条活动 Cached 关联；与当前音乐库比较，不论活动还是历史记录，歌曲持久 ID 命中数均为 0。来源路径一致，不能通过简单替换路径解决。
- 缓存登记的 573 张图片文件全部存在，文件头均为 JPEG；抽取两张，沿用页面的 WPF `BitmapImage` / `UriSource` / `.img` 路径和 360 像素解码方式，均成功。未逐张验证全部像素及数据库散列。
- 当前原生封面索引包含 5,136 条记录，3,066 首歌曲能直接读取原生封面来源。这些来源产生 290 个唯一缓存键，其中 277 个对应的本地图片文件已经存在。此数为直接来源匹配，不代表 277 张专辑或全部图片均已通过完整校验。
- 自动预缓存关闭，个人目录存在暂停标记；封面导入进度记录停留在此前的 2,949 首。音乐库“刷新”只读清单和封面关联，不会执行封面导入器的索引同步。

## 处理方向及限制

应依据当前本机原生歌曲 ID 与封面来源重新同步封面关联，再复用经过验证的现有图片，补充缺失封面，并刷新音乐库。不能仅凭专辑名称强行匹配，也无需清空已有缓存。需要让将来的音乐库身份变化能触发关联重建，并与用户暂停下载的偏好分开处理。

本轮只诊断，未重写个人数据库、恢复下载、修改设置或修复产品逻辑。ID 变化的具体发生时刻及原因未确认；换机、重建或重新同步资料库均不能仅凭这次结果断言。未使用本轮结果声称已修复显示。临时只读探针保存在忽略的 `.tools` 中，个人元数据和图片不进入 Git。
