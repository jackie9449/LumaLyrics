# Apple Music 原语言歌词

0.17.0 增加独立实现的本机 TTML 获取通道。参考 [AppleMusic_LyricsShower](https://github.com/Kanyooooo/AppleMusic_LyricsShower) 使用本机已加载歌词的思路，没有复制其代码、资源或翻译实现，也没有增加该项目依赖。

## 使用

在「设置 → 常规」保存“优先获取 Apple Music 已加载的原语言歌词”。默认开启。先在 Apple Music 手动展开当前歌曲的动态歌词，再点浮光的“重新查找当前歌曲原词”或主界面重新查词。

自动播放查词优先保留手动绑定及已有可靠缓存；缺少可靠缓存时，先检查本机 Apple Music，再根据联网设置使用 LRCLIB / 网易云原词。手动绑定不会因重新查词而被覆盖，需要用户明确解除锁定后才能重新自动获取。关闭联网查词不等于关闭本机只读通道。

本机通道需要客户端已加载当前动态歌词、原生文字可读、足够多的独特文本能够对应。窗口最小化、歌词面板关闭、资料不足或客户端不兼容时放弃本次本机采集，继续使用已有缓存或联网来源；不会自动展开 Apple Music、歌词或队列。它不是 Apple 官方全资料库歌词接口，也不能保证每首歌都可取得。

## 核对与存储

1. 记录当前 Apple Music 媒体会话、代次、录音版本及完整歌曲元数据。只读检查已展开的原生动态歌词，同时核对客户端当前歌曲的标题、艺人和专辑。
2. 只向 AppleMusic 进程申请查询与读取权限。优先查看同一进程生命周期内已找到的位置，再遍历可读已提交区域，优先私有可写区域；扫描上限为 384 MiB、10 秒、100000 个区域，最多保留 32 个有效文档。只解码完整的 UTF-8 / UTF-16LE TTML 根，单个片段最多 2 MiB；不保存周边内存、地址或转储。
3. 安全解析 XML，禁用 DTD 与外部实体，限制体积、深度和段落数。使用明确的逐行 begin 和 end / dur，支持标准并行容器的相对偏移及结束裁切。实机还观察到 Apple 的 Line 格式在 songPart 容器和段落上重复使用全曲绝对时间；仅当 Apple timing / key / songPart 标记齐全、每个分段的首尾与其所有歌词行边界准确一致时使用独立的绝对时间模式，并记录 timingModel。不将标准 TTML 任意解释为 Apple 格式。不支持的帧、节拍、顺序容器或缺失时间直接拒绝。保留正文、重叠人声及真实结束后的空白间奏，不凭空补四秒时间戳。逐字时间不作为更高精度播放时钟。
4. 以至少四条、合计至少六十个规范化字符的独特原生文本，按原生顺序核对 TTML；重复、冲突、逆序或多条竞争时间轴保持不确定。结束时重新检查同一进程生命周期、原生文本及实际媒体会话。切歌、取消、进程重启与过期结果不能写入当前绑定。再执行现有的歌词结构、覆盖与时长检查。
5. 保存的是检查通过的原词，而非人工语义认证。个人 lyrics.db 的 ProviderJson 保留完整 TTML、原词 SHA-256、TTML SHA-256、录音元数据、采集时间和核对方式，明确 semanticReview=false。仅取得无时间的可访问文本时不能导入为动态原词，也不会据此判定纯音乐。

个人备份从同一歌词数据库快照导出 LRC 和 originals/ 中可读的来源 JSON，并验证 TTML 与 LRC 哈希；恢复继续只写入新目录。来源 JSON 随录音身份分开，后台社区预缓存不能覆盖已有可靠 TTML 绑定。原词换版后旧中文译文保留在个人库，但只有精确原词哈希一致时才显示，手动译文不会被替换或借用新时间轴。

## 播放期间窗口与队列

自动刷新只读取已经展开的原生待播清单，不打开队列、不切换历史记录、不实现虚拟行或设置滚动位置。Apple Music 最小化时暂停原生队列读取；关闭的队列、历史页或无法读取的行明确标为不可用／部分列表，不伪造当前顺序。读取失败不会调用播放、Next 或窗口恢复操作。

主动选歌、专辑播放、插播和队列排序仍可在各自请求内短暂使用原生界面。操作和确认共用请求取消与窗口归属，恢复面板偏好；实际确认成功后才最小化 Apple Music。主动操作的确认读取与自动刷新分开，避免修复弹窗时破坏队列确认。

实现依据：[TTML 时间模型](https://www.w3.org/TR/2018/REC-ttml2-20181108/)、[VirtualQueryEx](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualqueryex)。核对原生文字不等于取得不可变的服务端录音 ID，文字完全相同、时间轴不明的版本仍需谨慎；不把自动检查称为人工逐首校对。
