# 原词获取与拒用原因

在「设置 → 资料库与歌词 → 歌曲」选择曲目，点击「准备所选原词与译文」。未采用原词的具体原因显示在每首歌曲的状态下；长内容可悬停查看全文，单选歌曲也会显示完整原因。准备结束会重新读取状态，成功后清除旧的拒用提示。

批量准备先使用本地可用原词并做一轮精确查询。通过检查的原词会在批次仍运行时显示。第一轮没采用的歌曲显示「等待补查」，第二轮再继续查其他候选、准备现有中文和导出任务。原词与中文都来自同一次网易云查询时，可复用该次结果，译文仍要通过与当前原词的对齐检查。

### 仅有静态歌词

播放查词、批量准备和后台预缓存会优先查找通过录音与时间轴检查的动态歌词。找不到动态歌词时，如果有与录音相符的静态正文，程序会保存下来供主窗口查看。已保存的静态歌词可离线查看；之后找到通过检查的动态歌词时，程序会自动升级。静态正文没有时间轴，逐行译文的准备会等动态原词可用。

在歌曲页右侧选择「仅有静态歌词」，可以集中查看自动保存和手动选用的静态原词。选中自动保存的静态曲目，再点「准备所选原词与译文」即可重查。已有手动绑定的曲目可右键「手动查词…」并确认新版本，也可以用「制作动态歌词…」打轴。

在歌曲列表右键点击一首歌，选择「手动查词…」，即可用这首歌的信息开始搜索，无需先播放。可用「手动填写歌名 / 歌手搜索」调整关键词，再预览并点击「使用所选歌词」。确认后，原词锁定到右键点击的那一首，自动查询会保留手动选择。之后使用资料库批量操作时，原来的多选仍可继续使用。

「更换歌词」中的「歌曲信息匹配度」只比较歌名、歌手、专辑与时长，100% 不表示歌词全文或时间轴正确。候选预览另行显示「自动检查通过」或「自动未采用」及原因；手动确认选用仍可用，选用后保持手动锁定。

合作曲目的完整歌手署名占 30 分。来源多列或少列署名时，如果一方的完整姓名都能在另一方找到，核对曲名、发行版及不超过 1 秒的时长差后，歌手项计 22 分。`and` 与 `&` 写法的差异也可通过这些证据确认。同版完整署名优先，歌词正文和时间轴仍需通过检查。

音乐剧来源若把专辑名缩成剧名，程序会核对对应的原版卡司及 Apple Music 所列的全部歌手。卡司或发行版有冲突时，候选需要手动确认。

来源用「Original London Cast」一类集体署名，Apple Music 列演员、指挥或乐团时，程序会核对完整专辑名、曲名、明确的原版卡司及不超过 2 秒的时长差。符合条件的卡司署名计 20 分，歌词还须通过正文与时间轴检查。只有集体署名的纯音乐标记需要手动确认。

日语曲目可对照歌名、歌手和专辑的罗马字、平假名与片假名读法。网易云和 LRCLIB 正常查询未命中时，会为能转写的名称尝试片假名关键词。歌名或歌手需要靠读法确认时，还需要专辑吻合、时长差不超过 2 秒以及录音版本和歌词时间轴检查通过。这些规则适用于歌曲页批量准备和播放查词。候选预览会显示采用读法匹配的情况。常用转写规则参考[日本文化厅《ローマ字のつづり方》](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/naikaku/roma/index2.html)和[《外来語の表記》](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/naikaku/gairai/honbun04.html)。

常规的网易云查词未得到匹配且名称有日语线索时，程序可比较 Apple Music 美区、日区的公开目录。同一 Apple 曲目 ID 提供正式罗马字和日本原名。程序再核对网易云目录的发行艺人、专辑、完整曲序、曲名、录音版本和时长。在多曲发行身份得到确认时，来源按主唱署名的曲目也可匹配。候选预览会显示「发行曲目已核对」，歌词正文与时间轴另行检查。已有证据可离线回读，同一专辑的在线目录可短期复用。[Apple 目录接口说明](https://performance-partners.apple.com/search-api)。

目录缺少曲目、版本不同或有多个可能的对应时，可从「手动查词…」查看候选。初次核对要查询两个地区的目录，所需时间随网络变化。查询受联网设置和取消控制。

## 从静态歌词制作时间轴

在「设置 → 资料库与歌词 → 歌曲」右键点击缺动态原词的歌曲，再选择「制作动态歌词…」。编辑器会载入已有静态原词，也可以粘贴文字或打开 TXT。每行放一句，空行跳过。

1. 点击「开始打轴」，在 Apple Music 播放这首歌。听到第一句开唱时按 **Enter**。
2. 每句唱完按 **Enter**，立即切换到下一句。连续唱的两句按一次即可衔接。
3. 切到下一句后，如果听到的是间奏，按 **G**。程序以刚才按 Enter 时标记的句尾为留白起点。听到下一句开唱，再按 **Enter** 结束间奏并开始这一句。最后一句唱完按 Enter，之后的尾奏也会留白。
4. **Backspace** 可撤销上一步。校对时可选中左侧一行改变起止时间，接受 `分:秒.毫秒` 或秒数。所有句子完成后，播放时可预览实际效果，再点击「保存动态歌词」。保存到浮光歌词个人库并作为手动原词使用。

打轴使用播放器的原始时间轴。歌词偏移继续作为播放设置应用。播放连接、录音或原词绑定变动时，编辑器会阻止混用时间点。文字输入框内保留正常编辑按键。

也可以在同一窗口选择「离线自动打轴」：

1. 在「对齐模型」选择与原词相符的模式。首次使用时点击「下载组件」。
   - 「法语 · W2V-BERT」和「德语 · W2V-BERT」与多语言模式共用约 2.6 GB 的组件，安装需预留 6 GB。法语重音、现代与弯撇号、德语变音字母和 ß 按所选语种编码。已经装好多语言组件时可直接选用。
   - 「日语歌声 · MMS」用本机词典把汉字和平假名、片假名转为读音，罗马音也可以作为原词输入。草稿和保存仍使用编辑器原文。组件约 1.6 GB，安装需预留 4 GB。模型权重采用 CC BY-NC-SA 4.0。
   - 「普通话歌声 · SOFA」适合人声清晰的汉字唱词。组件约 0.7 GB，安装需预留 2 GB。
2. 点「用 Apple Music 播放打轴」或「选择本地 WAV…」。程序先检查所选模型可识别的行数。覆盖不足时提示行号，可换模型、核对左侧原词，再重试。空行跳过，重复句按各自所在行检查。准备原词时，请按实际演唱顺序写出每次重复。
3. 检查通过后，在 Apple Music 将这首歌从头连续播放，或选择同一录音的 16 位 PCM WAV。拖动进度、暂停或提前切歌会中断采样。两种输入均支持最长 15 分钟。模型在本机分析，伴奏较重或有重复句时可能需要补标。
4. 在草稿里逐句试听。如果多句都早半秒，用「整体校准」输入 `0.5` 平移。可在左侧选中一行填写起止时间，或继续用 Enter / G 听打。句尾到下一句开唱的空白会保留。可撤销调整。
5. 时间补齐并核对后点「保存动态歌词」。保存时记录所选模型版本，动态歌词作为手动原词使用。

音频停留在内存。离线组件按需存入本机工具目录，换电脑可重新下载。草稿只在打开的编辑器中，保存时会再次核对原词绑定。已有可用动态歌词优先使用。

## 长尾段判断

两分钟以上歌曲，最后一句早于全曲 55% 时，程序会要求额外证据。满足以下条件可以通过长尾段检查：

- 来源同时提供全文，规范化后的同步正文与来源全文内容、顺序完全一致。
- 至少六个有效歌词组、80 个规范化字符、三组不同正文，时间展开至少一分钟。
- 原有录音版本、歌手、时长、时间戳范围、格式和正文覆盖检查通过。

只有器乐段落标记的组不算正文，也不能用来延长最后一句。没有全文、正文缺失或重排、时间点过于集中的候选仍需手动确认。以上是来源文字与时间范围检查，不代表已听音核对，也不会判定尾奏一定为器乐。程序不补造时间戳，不借用另一录音的时间轴。

## 常见原因与处理

| 原因 | 含义与处理 |
| --- | --- |
| 来源未返回歌词候选 | 本次查询无结果，可稍后重试或手动搜索/导入。 |
| 来源返回了曲目，但未能确认相同录音 | 歌词来源搜索返回了歌曲目录，可手动查看候选并确认版本。 |
| 已找到对应曲目，但来源未提供原词 | 录音信息已匹配。可查找其他歌词来源或导入原词。 |
| 来源暂不可用／部分来源暂不可用 | 查询尚不完整，稍后重试；不会将网络错误当成不存在歌词或纯音乐。 |
| 歌名、歌手、录音版本或时长不符 | 自动采用存在录音错配风险，先核对目标与候选版本。 |
| 合作署名有重合，但专辑或时长不足以确认录音 | 可在候选窗口核对具体发行版与时长。 |
| 同步歌词缺少纯文本中的较多内容 | 同步稿可能只是一部分，可更换来源或手动检查。 |
| 尾段较长且来源缺少全文对照 | 无法确认正文是否完整，保留手动确认途径。 |
| 时间戳超出歌曲时长／时间点过于集中 | 时间轴有风险，自动流程保留拒用。 |
| 歌词时间标签无效，需手动确认 | 来源内容无法解析为逐行时间点。可手动查看内容，寻找其他版本。 |
| 当前为手动静态原词 | 手动绑定继续保留；需要动态原词时，请明确更换或导入正确时间轴。 |

## 旧失败重新评估

匹配策略版本更新后，旧版六小时失败记忆失效；相关未完成的当前库成员重新排队，已绑定的手动歌词与可靠缓存保留。保留联网、自动预缓存与暂停偏好；关闭自动预缓存的用户可在歌曲页选择相关歌曲再准备，不会擅自启动全库任务。

当前规则下的新失败仍有重试间隔；来源不可用与候选检查失败分别记录。批量准备不受播放页失败记忆阻止，可主动重试。个人库重评前应保存一致数据库快照，逐首复核当前成员；已有正文、哈希、偏移及中文译文不因重评而替换。软件包和 Git 不包含个人响应、歌词、库清单或重评报告。
