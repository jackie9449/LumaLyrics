# 运行性能优化与测量（2026-11-17）

基线为 main / 4564902。软件外隔离目录使用原创 40 首 × 20 组歌词，每个任务携带同一专辑参考。优化前后各启动三个独立进程，使用相同 SDK 10.0.402、Release、设备及夹具；后两轮基线使用已冻结 album-translation 包的基础设施程序集。未操作真实播放或个人资料。

## 改动

- 任务列表与结果接收扫描在 SQLite 中排除 AlbumContext，再反序列化所需字段；不把整张专辑参考重复保留在列表对象里。默认完整请求读取、请求哈希、原始文件和实际导入验证保持完整。
- 任务复用先筛选同一原词绑定的 AwaitingResult 行，再解析候选；不再为导出下一首读取全部历史任务。接收扫描也先筛选待办，保留迁移状态检查。
- 主封面最长边最多解码到 1024 像素，小图不放大，宽高比保留；原始封面文件和高清计数不变。缩略图除 128 项上限外，增加总像素预算 4,194,304 像素（约 16 MiB 的 32 位像素缓冲）；刷新仍清理，淘汰图可重新加载。
- 正常歌词过渡只重设上一行和当前行；初始化、主题和布局变化仍全量刷新。过渡完成释放缩放、透明度和颜色时钟，使用当前 brush 身份避免旧完成回调打断新过渡。

## 原创夹具测量

| 指标 | 优化前（三轮） | 优化后（三轮） |
| --- | --- | --- |
| 40 首导出耗时 ms | 3105 / 3000 / 3289 | 1563 / 1546 / 1516 |
| 导出累计分配 MB（十进制） | 565 / 646 / 629 | 126 / 127 / 126 |
| 任务列表加载 ms | 87.9 / 102.4 / 88.1 | 82.4 / 82.1 / 80.9 |
| 任务列表累计分配 MB | 22.88 / 22.88 / 23.96 | 1.82 / 1.82 / 1.82 |
| 任务列表保留托管堆 MB | 5.460 / 5.460 / 5.456 | 0.324 / 0.324 / 0.324 |

导出平均约 3.13 s → 1.54 s，累计分配约减少 79%；列表保留托管堆约减少 94%。列表耗时改善较小，避免声称翻倍。测量中的 GC 仅用于隔离实验统计保留堆，产品没有新增强制 GC 或工作集裁剪。

4096×4096 的 32 位封面像素缓冲理论为 64 MiB，1024×1024 为 4 MiB；实际 WPF 解码尺寸由隔离窗口检查。该值不包含 WIC、编码数据、GPU/合成器及整个进程工作集，不能作为进程内存下降保证。

## 验证与限制

另用两个对应的 40 任务夹具资料目录，交替启动冻结旧包与新包各三次，均执行相同的 15 项隔离时钟检查（合计 90/90）。25 ms 轮询采样，取得主窗口原生句柄的时间旧包为 1433/1186/1186 ms，新包为 1239/1132/1184 ms；该指标不等于第一帧可操作时间，后两轮差距很小，不宣称稳定显著的启动提升。同轮检查期间采样私有内存峰值旧包 271.5/269.6/269.2 MB，新包 262.6/267.1/259.8 MB；均值约低 6.9 MB，仅限该启动/时钟夹具，不能外推为真实库长期内存变化。

单元测试、最终运行包检查及限制记录于 docs/development-log.md 的同日性能条目。单元验证轻量列表不改原始请求/身份、完整验证仍成功、已取消任务不复用；运行包验证大图、小图、长图、缓存淘汰/清理、歌词局部/全量刷新及完成时钟释放。

这轮没有重新设计所有启动服务、原生播放队列读取或字体系统。没有将当前真实进程的一次工作集读数与夹具进程比较，也没有据此声称整机内存、启动时间或 CPU 降低百分比。长期多小时使用、真实大资料库的所有界面、多屏高 DPI 的效果仍需持续观察。
