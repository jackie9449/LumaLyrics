# 0.16.4：主窗口译词开关与资料库成员范围

主窗口右下角的中文译文开关复用已保存的主窗口选项，与设置页双向同步，并保持悬浮译文独立。音乐库和后台准备读取原生主清单的持久 ID；本地曲目表中的其他记录不再冒充资料库成员。

297 项单元测试通过（Core 57、Infrastructure 240），包括原生主清单、无成员／空成员、非主清单同名伪装、其他播放列表、重复／缺失／损坏引用、后台查询范围、来源切换、旧缓存回退和手动原词及偏移保护。

完整 WPF 检查使用独立个人目录、原创双语文字和几何封面，不启动真实媒体或网络准备。覆盖中文显示、设置同步、保存、悬浮独立、键盘焦点、三主题和 1220／980／820 宽度的右下角布局，也回归资料库读取失败时的浏览保留。[解锁后源码回归](source-ui-check.json)和[自包含运行包复验](packaged-ui-check.json)均为 770/770，三主题画面见[主窗口译词预览](../screenshots-ui-v0164/README.md)。

Release 构建零警告、零错误。[运行包程序集校验值](binary-checksums.json)记录五个项目程序集；运行包使用随包 Microsoft host 执行，无需 SDK。软件分发边界及 32 类私人文件拒绝样例通过。

## 保留的早期结果

- 第一轮源码回归：768/769，一项既有的悬浮窗口激活检查失败，保留 `source-first-ui-check.json`。
- 增加资料库暂不可读的浏览保留检查后，第二轮：761/770。失败涉及既有玻璃截图、点击命中和原生交接等待检查，保留 `source-locked-ui-check.json`。其后独立检查确认桌面前台为 Windows LockApp；锁屏期间的原生桌面测量不能作为有效交互验证。未复制当时的屏幕图像。
- 用户解锁后重新执行相同检查，770/770 通过。原有断言、阈值和等待条件没有放宽；第一轮单项失败的原因不作确定归因。

本机资料库范围另在个人数据库一致副本上检查，确认浏览和准备队列等于原生主清单、用户指出的非成员被排除，原词绑定、手动标记、偏移、译文及封面数据库内容保留。个人歌曲名、ID、数量和诊断报告不放入仓库。

界面检查不证明真实 Apple Music 点播、媒体会话同步或歌词语义准确。原生主清单格式不受支持时会保留可靠离线清单并提示同步，不退回完整曲目表。
