# 0.17.0 验证

本版独立实现本机 Apple Music TTML 获取，并将自动队列读取与主动原生操作分开。全部软件界面验证使用独立个人目录与原创歌词／封面；真实歌曲、TTML、原生文字和播放诊断仅保存在软件目录之外的个人验证目录。

Release 构建零警告、零错误。322 项单元测试通过（Core 78、Infrastructure 244），覆盖标准与 Apple 标记时间模型、真实结束与空白间奏、重叠人声、安全 XML、UTF-8／UTF-16 完整片段、重复及竞争时间轴、手动原词与译文保护、哈希及个人备份恢复。

[最终源码完整 WPF 回归](source-ui-check.json) 为 992/992，使用最终的扫描字节预算限制与三主题设置界面。此前失败记录和修正范围保留如下。

[自包含运行包完整 WPF 回归](packaged-ui-check.json) 同为 992/992，使用随包 Microsoft host，SDK 列表为空。三主题的新设置页、悬浮独立外观、队列、托盘、个人库及本版新增检查均通过。

隔离 WPF 回归新增原词请求过期与忽略取消的结果丢弃、进程重启、原生文字改变、三主题设置入口，以及队列关闭／历史记录／虚拟化滚动偏好保护。主动操作的确认读取保留同一窗口归属，旧操作与已取消操作不能重新接管窗口。

[早期源码界面回归](source-first-ui-check.json) 为 982/983；新功能断言全部通过，失败项为既有 overlayCorners.frost-roundtrip.doesNotActivate。后续没有修改此焦点断言、阈值或等待条件；首轮仍使用较早的实现，之后又补上实机 Apple 绝对时间适配和三主题设置检查。

[加入全部检查后的首轮](source-before-fixture-layout-ui-check.json) 为 991/992，未通过 nativeQueue.virtualizedTailRead。新加的三枚面板开关使原创测试窗内容超过旧的 380 高度；将测试窗增至 560，保留每个虚拟化列表原来的 125 高度、70 行及全部尾部／完整性断言。[队列专项](development-queue-check.json) 47/47 通过。没有修改生产读取逻辑来跳过尾部或降低完整性要求。设置截图另在入场动效结束后采集，避免把动画中间的半透明状态用作预览。

[后续源码界面检查](source-focus-retry-ui-check.json) 为 991/992，队列尾部及本版全部新增检查通过，未通过既有 navigation.liquid.keyboardFocusAndHitTargetPreserved。焦点断言保持原样，保留该次记录。

真实 Apple Music 在播放中最小化时连续读取 12 次，原生窗口保持最小化、没有激活，当前录音与播放状态未改变。用户手动展开动态歌词后，再次连续读取 12 次，歌词保持开启、队列保持关闭；随后成功取得 44 行 TTML，采集前后原生文本与同一录音吻合，播放状态不变。来源记录使用 apple-absolute-section 时间模型并保留完整哈希链。这是单首实机样本与两个窗口状态检查，不代表全资料库或全部 Apple Music 版本已验证。

实机样本最初被标准父容器相对时间规则拒绝。检查个人目录里的文档结构后，确认 Apple 的分段和段落重复使用绝对时钟；使用原创测试素材新增专用边界检查后通过。没有把真实歌词复制到测试或 Git。

原生窗口截图接口先后返回 FrameArrived / window capture 超时，无法通过该工具操作歌词面板；用户随后手动展开面板完成实测。中间可见窗口样本受用户切换焦点影响，未将其当作“不激活”的通过证明。最终可见窗口及最小化样本均通过状态检查；实际原词采集使用可访问文字与只读进程内容，没有用截图推测时间戳。

分发边界检查与 2 类软件样例／36 类私人文件拒绝检查通过，新增拒绝 TTML、原词来源 JSON 与 originals/。个人备份包含同一数据库快照中的 LRC 和可读 TTML 来源 JSON，软件 ZIP 不含这些个人文件。

[脱敏实机摘要](native-summary.json)只保留次数、布尔状态和行数。实机取得的原词另在个人验证目录成功导出一致备份，包含 1 份 LRC 和原词来源 JSON，校验通过且没有警告；文件与实际内容未进入本目录。

自包含运行包的 Probe 也在无 SDK 的随包 Microsoft host 下校验上述备份并恢复到新目录，1 首动态原词、来源与哈希记录保留，没有警告；没有更改当前个人库或默认资料位置。

完整界面回归之后，补充运行包实机采集检查在初始 ElementFromHandle 观测阶段两次出现 UIA Timeout，随后的源码对照也同样超时，尚未进入 TTML 获取。私人失败记录保留，未记为采集成功；没有据此断定是包差异或确定外部原因，也不以 WPF 回归替代这项实测。之前源码的 44 行成功样本和备份实测仍如上记录。生产原词入口对超时按不可用处理，继续原有缓存／可用来源，不尝试展开原生窗口。
