范围更正（0.16.4）：下文历史曲目数来自整个本地曲目表，未区分尚未加入资料库的缓存记录，不能作为个人资料库或歌词覆盖总数。现在按原生主清单确认成员，详细行为见[音乐库说明](music-library.md)。历史验证记录保留。

2026-10-18。本次需求：提前为 Apple Music 资料库查词并保存本地；播放新歌曲时自动筛选并导入，日常无需逐首确认。

## 已实现的行为

- 自动发现本机 `Music/Apple Music/Apple Music Library.musiclibrary/Library.musicdb`，只读歌曲元数据。使用独立实现的有边界检查的解析器；声明曲目数与实际记录数不一致时拒绝把部分结果当作全库。
- 已实际读取本机 **3,219 首**，全部有歌名和时长，数量与声明值一致。覆盖的是本机已经同步的资料库；尚未同步到本机的云端变化需要 Apple Music 先同步。
- 曲目清单及队列存入浮光歌词 SQLite。已缓存、无可靠结果、网络错误分别记录。再次启动跳过已缓存项，续办剩余项目；每五分钟检查本机资料库更新。
- 背景请求串行节流，遵守 Retry-After。连续服务错误时退避；同一个本地库只允许一个预缓存进程。设置关闭联网、资料库窗口暂停、程序明确退出均可停止处理。
- 当前播放仍未缓存时优先查词，自动保存。查询失败时自动重试；找不到可靠结果时显示状态，保留后台队列，不要求用户点选候选。
- 处理已实测的“歌手 — 专辑”合并字段。与正确元数据匹配的重复来源记录按内容与时长排序，自动选取，不再因重复记录弹出人工确认要求。
- 已有手动绑定优先保留；兼容旧版合并歌手字段产生的缓存查找。数据库升级至 v4，迁移前生成 `lyrics.db.pre-v4.backup` 的一致 SQLite 备份。

## 自动检查的范围

录音匹配仍检查歌名、艺人、专辑、时长以及 Live/Remix/Acoustic 等版本标记，避免将同名歌曲或不同录音直接混用。内容检查包括空白/占位文本、有效时间点数量、时间戳越界、后半段覆盖以及同步歌词相对于来源纯文本的字符片段覆盖。

同一录音存在多份有效歌词时选择通过检查且排序最高的结果。没有时间戳的全文可以自动缓存为静态歌词；不会生成虚假的逐行或逐字时间。

这些是**结构与来源对照检查**，不是对官方原文的百分之百认证。没有权威全文、长器乐尾奏或来源文本本身缺失时，无法自动证明绝对完整；程序会保留检查结论，避免把明显片段当作完整同步歌词。曲目无公开歌词时不能凭空补出正确正文。

## 使用方法

从托盘退出旧版，启动新版 `LumaLyrics.exe`。默认开启“后台预缓存 Apple Music 全部资料库”。顶部“资料库 已缓存/总数”显示进度，点击可查看详情、暂停、继续或重试未缓存曲目。无需再次导出资料库或逐首确认。

首轮 3,219 首需要持续后台处理，完成时间取决于歌词服务、请求数量和网络；不会把启动扫描成功当成全部下载完毕。已获取的歌词保存在 `%LocalAppData%/LumaLyrics/lyrics.db`。程序关闭后本地结果仍保留。

## 验证

Release 构建 0 警告、0 错误。48 项自动测试通过（Core 29 / Infrastructure 19）：包含重复记录自动选择、截断排除、文本覆盖、错误艺人/版本/时长、资料库计数与损坏、只读原文件、队列续办、缓存跳过、手动绑定保护、暂停与独占处理。

实测 LRCLIB 查询为之前需要手动确认的歌曲自动选中记录，并通过同步/纯文本覆盖检查；筛除只覆盖前半段的候选。已在用户本地数据库开始实际预缓存；尚未完成全库下载，不能把当前缓存进度当作歌词覆盖率结论。

资料库格式兼容性依据本机实际解析结果，以及作者的格式研究：[Gary Vollink musicdb](https://home.vollink.com/gary/playlister/musicdb.html)、[rinsuki/musicdb2sqlite 字段研究](https://github.com/rinsuki/musicdb2sqlite)。这是本地格式适配，Apple 更新数据库格式后可能需要适配。Apple 的正式云端全库接口见 [Get All Library Songs](https://developer.apple.com/documentation/applemusicapi/get-all-library-songs)；本次本地功能无需配置开发者令牌。
