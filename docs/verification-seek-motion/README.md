专项通过实际 WPF 模板检查六套主题的点击位置映射、连续拖动预览、单次提交、两端、Esc、禁用/捕获丢失/隐藏取消、键盘操作、悬停中间帧与中断连续性、按压边界、确定进度的动画与时钟释放、按自身宽度移动的忙碌条、减少动画和卸载订阅清理。主窗口另检查固定时间轴下取消或拒绝后恢复单向绑定，以及播放刷新不覆盖拖动预览。输入事件为隔离验证，未将其等同于实机鼠标操作。

实机 Apple Music 没有开放 GSMTC 跳转能力，但原生 LCDScrubber 暴露可写秒制 RangeValue，范围与当前时长一致。播放状态下发出一次前跳 10 秒请求，实际新媒体时间轴确认成功；另一次回跳也通过确认，未调用播放列表或键鼠输入。测试后的暂停状态由独立读取确认恢复。现场录音、窗口信息与原生诊断全部保留在仓库外个人验证目录。

暂停时原生设置会影响恢复播放的位置，但该客户端的 GSMTC 时间轴没有立即更新。本次实现保持未确认提示并继续跟随实际媒体位置，不以原生滑块值单独宣称播放成功，不自动恢复播放或重发。实机验证不代表所有 Apple Music 版本均具有相同控件；未知、禁用、只读或范围不符的控件会被拒绝。
