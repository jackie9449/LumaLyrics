# 0.18.0 验证

主应用六套主题共用业务逻辑，分别提供字体、排版、面板形状、边框、封面留边、导航和背景构成。液态玻璃保留原有基本形态及封面取色；雾白同样随封面取色，其余四套固定配色。悬浮工具栏的既有浅色配色单独保留，不依赖重制后的应用雾白配色。

所有界面验证使用软件目录之外的独立个人目录，不启动实际媒体会话或网络预缓存。曲目、歌词、图片及队列为原创素材；报告及截图不包含真实 Apple Music 内容。本次没有改变原生播放或歌词获取逻辑，不能用界面回归宣称实机 Apple Music 行为已重新验收。

## 检查范围

- 六主题的保存与恢复、未知标识回退，以及全部悬浮主题的独立状态。
- 重制及新增主题在底色、悬停色、选中色和控件底色上的文本对比度；四套固定主题不会因封面改变配色。
- 实际渲染的结构差异，包含导航宽度、封面留边、面板形状、边框、标题顺序和字体，避免只验证颜色表。
- 播放页在 820、980、1220、1440、1920、2560 宽度和宽而矮的窗口中的歌词、封面、播放控件与队列边界；封面保持正方形。
- 专辑、歌曲、队列、设置、导入、校对及悬浮外观编辑的统一控件；窄窗主题画廊切换为单列。
- 悬停、按压、键盘焦点、选中、动画中断、完成清理、关闭窗口及减少动画；各主题的导航图标保持固定、单色且处于点击范围内。
- 原有个人数据、手动歌词和译文、队列顺序与重复位置、悬浮玻璃、字体预览及托盘继续回归。

## 开发检查记录

首次主题专项为 30/36。新增验证在悬浮窗尚未应用自身外观前就记录了工具栏颜色，因此六个独立性检查均失败；随后明确先应用独立外观再记录基线，未修改独立性断言。另发现原创封面被仍在完成的手动歌曲缓存读取清空；先等待该读取完成再设置验证封面，并新增实际 BitmapImage 和占位图隐藏检查。[首轮结果](development-first-theme-check.json)保留。

修正后的主题专项为 42/42，真实 900 × 900 原创封面被显示，六套主题、设置卡片、窄窗画廊及悬浮独立性全部通过。此后补充了结构差异检查和各页面的统一形状。完整回归与运行包的最终结果将在本目录保留。

[开发阶段首次完整回归](development-first-full-ui-check.json)为 1505/1507。雾白面板取色过于接近纯白，8 位颜色量化后在不同封面间无法保持可见区别；提高其轻微色彩含量，保留整体明亮。柔塑的额外歌词字号倍率与原有高亮验证不一致，取消额外倍率，保留既有原词和译文的字号层级。两项断言均未放宽。
